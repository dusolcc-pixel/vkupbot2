VKUPBOT2 - GOOGLE DRIVE + GOFILE WORKER SETUP (UPDATED)
=======================================================

The bot supports Google Drive file links and GoFile folder links.
Google Drive settings remain unchanged. GoFile now uses a dedicated JSON
API endpoint and does NOT request or scrape the /admin HTML page.

GOFILE WORKER CONFIGURATION

In src/themes/public_shared_dark.js on the GoFile Cloudflare Worker, set:
  LINK_SIGNING_SECRET = a private random value (at least 32 characters)
  BOT_API_KEY = a different private random value (at least 32 characters)

Keep AUTHENTICATION set to "true". OPTIONAL_USER and OPTIONAL_PASS protect
the human-facing /admin page only. They are not needed by the Telegram bot.

BOT HOSTING ENVIRONMENT VARIABLES

  GOFILE_WORKER_URL=https://your-gofile-worker.workers.dev
  GOFILE_API_KEY=the-exact-same-value-as-BOT_API_KEY

You no longer need these GoFile bot variables:
  GOFILE_WORKER_USERNAME
  GOFILE_WORKER_PASSWORD
  GOFILE_ADMIN_USER
  GOFILE_ADMIN_PASS

Google Drive variables (unchanged):
  GOOGLE_DRIVE_WORKER_URL=https://your-google-drive-worker.workers.dev
  GOOGLE_DRIVE_WORKER_TOKEN=your-worker-token-if-configured

Use the base Worker URL only. Do not add /admin or /api/folder-links to
GOFILE_WORKER_URL. The bot calls /api/folder-links?folder=... internally.
That endpoint returns JSON containing signed /d/<token> links, not admin HTML.

WHY TWO GOFILE SECRETS?

- LINK_SIGNING_SECRET signs individual download URLs. Keep it private.
- BOT_API_KEY authorizes the bot to ask the Worker for a folder's file links.
- OPTIONAL_USER / OPTIONAL_PASS only protect your browser-based /admin page.
  They are not included in generated download URLs and are not required by bot.

HOW TO USE

Send one or more URLs to the Telegram bot, one URL per line. GoFile folders
return one signed download URL per file. Google Drive file links continue to
use the existing /generate.aspx endpoint. Existing bot interface and other
bypass routes are unchanged.

TROUBLESHOOTING

- HTTP 401 from /api/folder-links: BOT_API_KEY and GOFILE_API_KEY do not match,
  or the key is still the placeholder.
- HTTP 500 while generating signed links: check that LINK_SIGNING_SECRET is
  set to a real private value at least 32 characters long.
- HTTP 502: the Worker could not retrieve the folder from the GoFile API.
  Check AUTH_TOKEN, GoFile API access, and the folder ID.
- Visiting the public Worker root should show only the service status message.

The bot lists regular files in the submitted folder, up to the configured
MAX_CLOUD_LINKS_PER_FOLDER limit. It does not recursively traverse subfolders.
Do not commit any real API keys, passwords, or signing secrets to public Git.
